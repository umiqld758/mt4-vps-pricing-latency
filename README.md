## MT4 1ターミナルに必要なメモリは「数百MB」か「1GB」か

結論から書くと、1口座＋EA 2〜3本なら2GB、口座3つ以上かインジケータの多いテンプレートなら4GBを起点にしてください。1ターミナルあたりの実測値は資料によって開きがあり、次の3つの数字が確認できています。

- チャート4〜5枚にEA 1〜2本で数百MB。インジケータを重ね、ヒストリーが長く、ティック単位で動くEAなら1GB近くまで行く（MassiveGRID）
- 1ターミナルあたり約1GBを見込み、EAや他のソフトのぶん余裕を足す（LightNode）
- 1GBでMT4を約6本、ただしバックテストを回さない場合（VPS Malaysia）

幅があるのは、チャート枚数とインジケータの重さで消費量が変わるからです。実運用の目安としては、1ターミナルあたり0.3〜1GBの範囲で考え、2GBあれば1口座の運用は収まり、4GBあれば口座を増やしても詰まりにくい、という理解で足ります。

CPUを増やしても実運用は速くなりません。MT4はチャートごとの処理をシングルスレッドで回し、大半の時間は次のティックを待っています。メモリが足りないとターミナルが落ちますが、vCPUが1つ足りないことでEAの発注が遅れる場面は、スキャルピングでもなければほとんどありません。

## 設置場所はブローカーのサーバーで決める

VPSの遅延は、VPSの性能ではなくブローカーのサーバーとの距離で決まります。同城のデータセンターなら数ホップの城域ネットワークで済み、値の付け直し（リクオート）や逆指値の滑りが減ります。2026年10月時点で各社が公開しているサーバー情報では、IC Markets、FP Markets、Axi、Global PrimeがEquinix NY4、FxPro、Admirals、Darwinex、BlackBullがLD4かLD5、FXTMがフランクフルトです。MassiveGRIDは自社表記で、ニューヨーク、フランクフルト、シンガポールの各拠点から同城のブローカーまで1ms未満、ロンドンのブローカーまで10ms未満としています。

AvaHostで確認できた設置場所はキシナイウではなくキシナウ（モルドバ）の1拠点です。日本国内や東京リージョンは今回の資料では確認できていません。ヨーロッパのLD4/LD5やフランクフルトにサーバーを置くブローカーなら地理的な相性は悪くありませんが、NY4のブローカーやアジアのブローカーだと遠くなります。

注文前にやることは1つです。MT4のログイン画面に出るサーバー名を確認し、ブローカーの公開情報と照らして、候補のVPSからpingを打って数字を見る。ブローカーはサーバーを移すことがあり、同じブローカーでもプラットフォームや法人ごとに都市が違う場合があります。

## 格安VPSでEAが止まる3つの落とし穴

**1. リモートデスクトップは「切断」で閉じる。「サインアウト」は禁止**

RDPのウィンドウを閉じるのは切断で、VPS側のセッションは残ります。スタートメニューからサインアウトするとセッション自体が終了し、起動中のMT4も一緒に落ちます。翌朝ログインしたらポジションが放置されていた、という事故はここで起きます。

再起動やメンテナンスのあとに自動で戻す設定も必要です。MT4のショートカットをWindowsのスタートアップフォルダ（`shell:startup`）に入れ、MT4の設定で「起動時に個人設定とデータを保持する」にチェックを入れておくと、再ログイン後に口座とEAの状態が復元されます。設定を忘れると、EAは動いているのに次の起動で全部外れる、という状態になります。

👉 [AvaHostのWindows VPS（RDP接続・管理者権限）を見る](https://my.ava.hosting/aff.php?aff=15562)

**2. 複数口座は1ターミナル1口座。フォルダを分けるか `/portable` で起動する**

1つのMT4ターミナルがログインできるのは1口座だけです。2つ目の口座を同じターミナルで開くと、チャートもEAも上書きされます。別フォルダに2つ目をインストールするか、`/portable` パラメータを付けたショートカットでコピーを起動してください。ログイン情報、チャート、EA、ログが独立するので、片方が落ちてももう片方は動き続けます。

**3. MT4のインストーラはブローカー版しか使えない**

MetaQuotesは自社サイトからのMT4配布を終了しています。ブローカーのブランド版インストーラにだけ、そのブローカーのサーバーリストが入っています。VPSのデスクトップでブローカーの公式サイトを開き、そこからダウンロードしてインストールしてください。Windows Server上でもWindows 10や11と同じ手順で動きます。

Macしか持っていない人も、RDPクライアントでWindows版のMT4をそのまま操作できます。スマホアプリは同じ口座を監視する用途で、EAの設定はVPS側で行います。

## ブローカー無料VPSと有料の格安VPS、どっちが得か

ブローカーが提供する無料VPSは、月間の取引量を条件に、小さい共有インスタンスを1拠点だけ用意する形が一般的です。軽いEAを1口座で動かすならこれで足ります。取引量が落ちると回収される点が、有料との決定的な違いです。

有料の格安VPSで買えるのは、都市の選択、管理者権限、リソースのコントロール、そして取引量に関係なく使い続けられること。AvaHostは全プランで専用IPv4と管理者権限が付き、RDPで接続して自由にソフトを入れられます。無料VPSで「EAは動くが、回線もメモリも隣の人と共有で、いつ取り上げられるか分からない」と感じているなら、月5ユーロを固定費に変える意味はあります。

## 専有コアに課金すべき人、しなくていい人

専有コアが必要になるのは、スキャルピングとニュース取りのEAだけです。ミリ秒単位で発注のタイミングが決まる戦略では、隣の利用者のバックテストでCPU時間を奪われると結果が変わります。スイング系やトレンドフォロー系なら、共有コアで実害は出ません。

「専有に上げるといくら余計にかかるか」の目安として、MassiveGRIDの専有コアプランは月額9.73ドルから（Windows Serverライセンス込み）で、共有コアの最安プランとの差は約6.86ドルです。AvaHostは全プランでvCPUを固定割り当てとしているため、上位プランに上げる理由はコアの取り合いではなく、メモリとコア数そのものの不足になります。多くの読者は、上位プランに上げる必要はありません。

## バックテストは実運用と同じサーバーに置かない

MT4のストラテジーテスターはシングルスレッドで動きます。vCPUを増やしても1本のテストは速くなりません。効くのは複数のテストを同時に回すときだけです。全コアを使いたいならMT5に移すほうが早いです。

バックテストは実運用のターミナルとCPUを奪い合います。同じサーバーで回すなら、EAが動かない時間帯に限定してください。最適化を頻繁に回すなら、実運用とは別に1台用意したほうが結果的に安く済みます。

## 注文前の最終判断

最後に、構成ごとの選び方を整理します。

- 1口座＋EA 2〜3本、インジケータは標準的 → AvaHostの最安プラン（月額5.00ユーロ）で足ります

- スキャルピング・ニュース取り → 専有コアのプランを検討する価値があります
- バックテストを頻繁に回す → 別サーバー、または取引時間外に限定
